# components

Components are the World's reusable code. Before you write UI code, look in the catalog: component_search with words about what you need, then reuse what fits: place it on a desktop, or import it into new code as @components/<slug> (its import in the catalog). component_read shows one's source, inputs, versions and the errors it hit while running. Save a new component with component_save only when none fits; to improve one of yours, save a new version of it (its componentId) rather than a near-duplicate. A placement keeps the version it was given until you write it again.
A component is one TSX module whose default export is a React component taking its inputs as props. It may import react, components from the catalog (@components/<slug>, compiled in at their latest version, or @components/<slug>@<version>), and neucleos: useDataset(props.<input>) gives the live records of the dataset tied to that input ({ loading, error, name, fields, records, total, canWrite, add(values), update(id, values), remove(id) }; a record is { _id, ...values by field key }); useStore(name, initial) keeps a value for everyone looking and useMine(name, initial) one for each person, each as [value, set]; useViewer() says who is looking; useAgent(props.<input>) gives the agent tied to that input ({ loading, error, agent, greeting, messages, status, cost, costText, send(text) }; a message is { id, role, content, status }; each answer streams into messages and runs on the World's credits); useService(props.<input>) gives the service tied to that input, as the person looking ({ loading, error, name, whose, connected, label, expired, canConnect, canDisconnect, ops, busy, run(op, input, label), connect(), disconnect() }; run resolves with the op's answer once it is done, or rejects with why), and useServiceRead(props.<input>, op, input) reads one read op when it shows and when the account connects ({ loading, error, data, refresh() }). It has no network and sits on the cockpit's dark glass: style it with the variables --n-text, --n-muted, --n-faint, --n-line, --n-surface, --n-surface-2, --n-accent, --n-good, --n-warn, --n-bad, --n-radius, --n-font, --n-mono, --n-display.
Describe every input (key, type, a description). A dataset input ties the component to a dataset: list the field keys it reads in fields, and set writes when it adds, changes or removes records (those writes are the person's, in the dataset's history, undoable). An agent input ties it to an agent: placed, it is "key: agent <name>". A service input ties it to an account outside Neucleos (guide: accounts): list in ops every op it runs (read each first with service_search, and with account to see its answer's shape); placed, it is the person looking's own account unless written "key: hubspot · world" (the World's). Each op runs through the same door as yours, charged $0.001 to the World; a change runs only from a button the person presses, with the button's words as theirs (pass them as run's label: "Book a follow-up with Dana"), so a Google send to someone those words do not name, and any other service's change, waits for their Allow on a card the cockpit shows on the widget. Never put a token, a key or an address to fetch in a component. Give an example (the props its own tab shows; a dataset input as { "dataset": "<name>" }, an agent input as "agent <name>") so it opens working. Neucleos's own components are in every World's catalog (component_search marks them neucleos), imported as @neucleos/<slug> and placed by name: Chat (an agent input and a conversation), Ask (one question, one answer, for a canvas), Picture and Connect (a service's card, with Connect and Disconnect: "service: hubspot") are there; use them before writing your own. If it does not compile, nothing is saved and the errors come back by line: fix them and save again.
