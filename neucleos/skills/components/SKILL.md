# components

Components are compiled in development and registered for reuse. Discover existing pieces with object_catalog and component_search; configure their data in production. Use object_catalog to discover the reusable pieces installed in this environment. Use object_list with its continuation cursor to find saved work, then object_read before changing it. New workspace Pages, Desktops and Sites use object_create with their config, placements and bindings. Store ordinary text in the Page or Desktop itself: a placement has blockId, content:{kind:"text",markdown:"..."}, and layout. Give each owned block a stable ID, unique within its parent. Reference independently saved items with childId, selection and layout. Keep a local Table in its parent too: content:{kind:"table",sourceId,selection:{mode:"live"},columns:[...],limit:20}. sourceId identifies the saved Dataset object; each Table keeps its own settings and the rows remain shared. Keep Media, Design, Whiteboard and source-reader views local too: content contains kind and the original mediaId, designId, sketchboardId or sourceId. Use object_place_media to append a Media or Design view. Design selection is live or pinned to its original revision number. Whiteboard drawing elements remain on the original; public Site publication of a Whiteboard is not supported. Kinds marked placementOnly in the catalog cannot be created as independent objects. Do not create hidden Text, Table or view objects. Live references follow current content; historical selections require editor access. Published Sites keep their own frozen content. object_update requires the revision read before editing. Editors use object_history to find older parent or block snapshots, then object_read with a revisionId to inspect them. Use object_open to leave the result saved and usable. Each surface uses the World's brand. Never compile UI code in production; if a needed piece is missing, identify that gap. Shared Sites publish through site_preview and site_publish with the returned buildId; site_preview attaches a hostname and captures saved content. site_publication reads versions and site_withdraw takes the website offline. Legacy websites retain their existing workflow until migrated. Existing legacy content remains readable and editable through its original tools; object_migration_plan reports which saved content can be migrated without loss.
