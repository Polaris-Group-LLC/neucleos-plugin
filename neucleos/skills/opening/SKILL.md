# opening

Activate this workflow when the person addresses you as Cleo, asks to open the Neucleos app or workspace, or explicitly asks to work in Neucleos. Merely installing the plugin does not turn ordinary conversations into Neucleos sessions. A question about the product is not by itself a request to open it.

Use the host context and browser tools already supplied by your session. Do not infer the host from the model name, OAuth client, or a general preferred-browser setting. Neucleos supports Mac apps and web browsers; a CLI is not a supported user experience.

1. On first activation in this conversation, inspect the current host's available browser tabs before doing the requested Neucleos work, including a version check. Reuse the correct existing Neucleos tab; do not open a duplicate or disturb an existing split view. If tab inspection is unavailable, say that you cannot check whether it is already open rather than claiming it is closed or absent. Only ask which host they use if the session context genuinely does not establish it.
2. Use the connected Neucleos tools. If the host asks to connect or authorize Neucleos, let the person finish that secure sign-in/consent flow, then resume. Never ask for passwords or verification codes in chat. When a link is needed, call cockpit_link for the requested World/artifact, or without arguments for the workspace. The production workspace is https://v6.cockpit.neucleos.app/.
3. In a native Mac app, open or reuse Neucleos in that same app's built-in browser tab, beside this conversation. Do not try Chrome first or silently launch an external browser. This applies to both ChatGPT and Codex modes of the Mac app and to the Claude Mac app. If that surface cannot be opened with the available tools, explain the limitation and provide the link.
4. In a web browser, use another tab of that same browser. If the conversation and Neucleos are already side by side, leave them there. When the host provides an actual split-view operation, use it to place Neucleos beside this conversation, then verify the result. Being able to read splitViewId does not mean you can create a split view. Do not assume an extension is installed or can be controlled through MCP, and do not invent browser operations.
5. In Chrome without a usable split-view operation, give a short, concrete handoff. If Neucleos is not open and you cannot arrange it automatically, provide an Open Neucleos link and say: "Right-click Open Neucleos and choose 'Open link in split view' to see it beside this chat." If its tab is already open, say: "With this chat tab active, right-click the Neucleos tab and choose 'New split view with current tab'." Use the matching instruction, not both. In other browsers, use only controls known to be available; otherwise give the link for another tab and explain the limitation. An extension is optional, not required to use Neucleos.
6. Check the resulting page and say where it opened. Returning a link, submitting a navigation, or receiving artifact_open.opened is not proof that the browser displayed it. Do not claim split view or a browser check succeeded unless observed; distinguish the person's confirmation from your own inspection. Reuse its existing browser sign-in. The MCP connection's authorization and the browser's session are separate; if the page requests sign-in, let the person complete it there and then resume. Only a link explicitly returned with signsIn:true establishes a sign-in handoff; never assume every link signs them in. Use world_list to confirm the connected account and available Worlds; a different browser sign-in may need the person's attention. If you cannot open or inspect the browser, provide the truthful handoff and continue useful requested MCP work without pretending the browser step was completed.

After the workspace is available, continue the requested work through Neucleos's MCP tools with the person's access. Do not repeat setup in the same conversation. Respect an explicit request to keep Neucleos closed or use another destination.
