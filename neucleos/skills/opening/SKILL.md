# opening

Activate this workflow when the person addresses you as Cleo, asks to open the Neucleos app or workspace, or explicitly asks to work in Neucleos. Merely installing the plugin does not turn ordinary conversations into Neucleos sessions. A question about the product is not by itself a request to open it.

Open Neucleos beside the surface where the person is viewing this conversation now. The same session may be open in a web browser and a desktop app simultaneously, and a web session may control the desktop app's browser remotely. Browser access is not evidence of the person's current viewing surface. Neucleos supports Mac apps and web browsers; a CLI is not a supported user experience.

1. Resolve the current viewing surface before choosing browser tools. The person's latest explicit location or destination wins, then explicit current host/interface context. A host statement that this is a web chat takes precedence over a built-in-browser preference. Where a session originally started may be stale after a switch. Tool availability, model name, OAuth identity, saved memory, preferred-browser settings and an online desktop app do not establish where the person is viewing the chat. Treat names such as remote-devices as a warning that controls may reach another surface, not as a reliable app-versus-web classifier; their absence is not proof either. If the surface remains unclear or signals conflict, ask once: "Are you viewing this chat in the desktop app or a web browser right now?" Provide the workspace link while awaiting the answer and continue useful MCP work. Do not automatically open both places. Keep the answer as conversation context and update it when the person switches; do not save a permanent location preference unless asked.
2. On first activation, inspect available tabs in the chosen surface before other Neucleos work, including a version check. Reuse the correct Neucleos tab there; a tab in a remotely connected desktop app does not satisfy a web-chat opening request. Do not open duplicates or disturb a split view already beside this conversation. If those tabs cannot be inspected, say so instead of claiming Neucleos is absent. Unavailable controls in the chosen surface do not authorize switching to another surface.
3. Use the connected Neucleos tools. If the host asks to connect or authorize Neucleos, let the person finish that secure flow, then resume. Never ask for passwords or verification codes in chat. When a link is needed, call cockpit_link for the requested World/artifact, or without arguments for the workspace. The production workspace is https://v6.neucleos.app/.
4. When the person is viewing a native Mac app, open or reuse Neucleos in that same app's built-in browser tab, beside this conversation. This route takes precedence over a general preferred-browser setting unless the person explicitly requests another destination. Do not try Chrome first. This applies to ChatGPT and Codex modes of the Mac app and the Claude Mac app. If that surface cannot be opened with the available tools, explain the limitation and provide the link.
5. When the person is viewing a web browser, use another tab of that same browser, even if a connected desktop app or a built-in-browser preference is present. If the conversation and Neucleos are already side by side, leave them there. Use a split-view operation only when the available tools actually support it. Reading splitViewId does not mean you can create a split view. If the matching browser controls are unavailable, provide a link for that browser; do not fall back to a remote desktop pane. Do not assume an extension is installed or controllable through MCP.
6. In Chrome without a usable split-view operation, give one matching handoff. If no existing Neucleos tab is known, provide an Open Neucleos link and say: "Right-click Open Neucleos and choose 'Open link in split view' to see it beside this chat." If its tab is already open, say: "With this chat tab active, right-click the Neucleos tab and choose 'New split view with current tab'." In other browsers, use only known controls; otherwise give the link for another tab. An extension is optional.
7. Immediately inspect the resulting page using available page-reading or screenshot tools as part of the opening request, without asking whether the person wants this read-only check. Respect any permission prompt imposed by the host. Confirm whether the page shows the workspace, a sign-in screen, an error, or is still loading. Check visibility in the chosen surface: a hidden pane or a page loaded on another device is not visible delivery beside this chat. Reveal it only if it is the intended app and the tools support that; otherwise explain where it actually loaded and give the correct link. A URL, navigation command, artifact_open.opened, or readable hidden page alone does not prove completion. Do not claim a layout, account, World, or visible page you have not checked; distinguish the person's confirmation from your inspection.
8. Reuse the browser's existing sign-in. MCP authorization and the browser's session are separate; if the page requests sign-in, let the person complete it there and then resume. Only a link explicitly returned with signsIn:true establishes a sign-in handoff. Use world_list to confirm the connected account and available Worlds, not to infer the browser's account or currently viewed World. If opening or inspection is unavailable, give a truthful handoff and continue useful requested MCP work without claiming browser verification succeeded.

After the workspace is available, continue the requested work through Neucleos's MCP tools with the person's access. Do not repeat setup in the same conversation. Respect an explicit request to keep Neucleos closed or use another destination.
