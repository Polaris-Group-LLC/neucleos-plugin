# desktops

A desktop is a surface of things you and the person make and use together: answer with things they can use, not only prose. Read it first with desktop_read (every thing as its block, with what people did in it, and what changed since you last read). Write on it with desktop_write, in the block format: a line "@@kind Name" opens a block, its lines are the thing, and the next "@@" line or "@@end" closes it; text outside blocks is what you say on the desktop. Kinds: note (text); doc (markdown); list ("- [ ] item", "- [x] done"); table (a pipe table, header first; it becomes a dataset; "· live <dataset name>" shows an existing dataset instead); board ("## Column", then "- card" lines); poll (the question, then "- option" lines; "· multi" after the name allows several picks); quiz ("? question", "- option", "* the right option", "> why"); form (an intro line, then "- Label: text|long|number|date|email|yes|choice (a, b)", and "= default" under a field); link (a URL, then a note); component (a component from the catalog: "use: <its name>", optionally "version: N" (the latest otherwise), then one "key: value" line per input; "key: dataset <name>" ties a dataset to a dataset input; numbers, yes/no and lists as JSON); sketchboard (its body is elements in the sketchboard format (guide: sketchboards), drawn on a sketchboard of its own and shown live; "· live <sketchboard name>" shows one that exists). "@ x,y" in a header places a thing (and "WxH" sizes it); without it, it goes in the next free space. A block with the kind and name of an existing thing rewrites it in place, keeping what people did in it. One-line acts: "@@open Name" brings a thing into view, "@@tuck Name" puts it away, "@@move Name @ x,y", "@@delete Name". One write is one change in the desktop's history: dataset_history, dataset_change and dataset_undo work on it with the datasetId desktop_read gives. A write that would overwrite someone's change since you last read (rewriting a thing whose content, name or variant they changed or that they tucked away, moving one they moved, deleting one they changed in any way, rewriting a table whose rows they changed) is refused with who changed what, and nothing is written: read it again, then write once more, keeping their changes. Votes, answers, ticks and where they dragged a thing never stop a rewrite: it keeps them. When someone presses Send to Cleo on a form, its state line says they sent it to you; in a session started with Neucleos sends (npm run cleo) it also arrives at once as a <channel source="neucleos-inbox"> message: answer it on that desktop.
