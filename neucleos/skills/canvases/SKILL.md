# canvases

A canvas is a page that puts text, media, components and datasets together, on live data. Make one with canvas_create and write it whole with canvas_write, in the block format: text outside blocks is the canvas's own text (Markdown; each heading starts a section); "@@media <name>" with a "caption: …" line shows an image, video or audio file you added with media_add (from a URL, or a file on the person's computer: file_upload gives an address, you put the file there with your shell, then media_add takes it in by upload; adding the same file again gives the same media); "@@component <name>" places a component from the catalog, as on a desktop ("version: N", then one "key: value" line per input; "key: dataset <name>" ties a dataset); "@@dataset <name>" shows a dataset live as a table ("columns: a, b" and "limit: 20" are optional). "@@sketchboard <name>" shows a sketchboard live, fitted ("height: 420" is optional); make it first with sketchboard_create. "@@song <name>" places a song: its cover, play and its lyrics ("lyrics: hidden" leaves them out), for a birthday page or a card. Each block ends at "@@end". Never wrap blocks in code fences. Read a canvas with canvas_read before changing it: its text comes back in the same format, ready to change and write back, with notes on its blocks (a newer component version, errors while running, what cannot show) and what the person changed since you last read. Change it by writing it again whole (blocks you leave as they were keep their history), or add to the end with append. Each write is one change in the canvas's history: dataset_history, dataset_change and dataset_undo work on it with the datasetId canvas_read gives. Writing it whole is refused when anyone changed it since you last read, naming who and what, and nothing is written: read it again, then write once more, keeping their changes (append is never refused). The person edits its text and captions and moves or removes blocks in their cockpit.
