# sites

Use object_catalog to discover the reusable pieces installed in this environment. Use object_list with its continuation cursor to find saved work, then object_read before changing it. New workspace Pages, Desktops and Sites use object_create with their config, placements and bindings. Create Text and other registered pieces from data, then place the same object where needed. Live selections follow later revisions; pinned selections name one revision. object_update requires the revision read before editing. Use object_open to leave the result saved and usable. Each surface uses the World's brand. Never compile UI code in production; if a needed piece is missing, identify that gap. Shared Sites publish through site_preview and site_publish with the returned buildId; site_preview attaches a hostname and captures saved content. site_publication reads versions and site_withdraw takes the website offline. Legacy websites retain their existing workflow until migrated. Existing legacy content remains readable and editable through its original tools; object_migration_plan reports which saved content can be migrated without loss.
Published website workflow: A Site composes the same registered Pages and pieces as the workspace. Find existing Sites with artifact_list, then read their composition with object_read. site_create makes a private shared Site; use object_create and object_update to add Pages and route placements. Site configuration sets its homePath, description, language and redirects. Each route has a path, navigation label and optional title/description. Each Page contains registered pieces configured with saved data, styled by its World brand. Never compile customer UI code in production.

Publication: site_preview captures the selected revisions of the Site, Pages and nested pieces, released brand, Media and Table data. It assigns a free hostname when needed, returns a private preview, route changes and buildId. Inspect the preview, then site_publish with that exact buildId publishes it using the connected person's founder/admin authority. Later draft edits remain private. site_publication lists saved versions and the current build. site_publish with an older buildId rolls back; site_withdraw removes public delivery and stops responses while keeping history. Address changes use the existing site administration controls. Address caches may take up to 30 seconds to update.

Published Forms, Polls and Quizzes use the existing saved interaction model and continue accepting responses while drafts advance. Preview controls never send responses. Tables choose publicationData snapshot (default) or live. Snapshots include only selected columns and all rows within the existing 5000-row bound, with paging and CSV; live Tables require a public Dataset and enforce its current access. Text and media are readable without JavaScript. Saved pages and files are delivered from R2 even when Convex is unavailable; live data and responses then report unavailability. Preview requires ownership or public access for each included source and supports up to 650 KB of saved composition and 500 units per Source.

Existing legacy sites retain site_read/site_write and their original publishing workflow until migrated. Use object_migration_plan before object_migrate. Supported Page routes retain addresses, history and SEO; custom compiled sections, HTML and styles are reported as requiring the legacy renderer. Do not overwrite them to force migration.
